**Session 2 - S3 Storage Fix (CRITICAL BUG FIX):**
1. **Discovered DynamoDB 400KB item size limit** - files > ~300KB were failing with 500 error
   because DynamoDB items cannot exceed 400KB, but the app advertised 5MB file uploads
2. **Added S3 bucket for attachment file storage** to CDK stack:
   - `canopy-attachments-{account}-{region}` with AES256 encryption
   - Lifecycle rules for cleaning up incomplete multipart uploads
   - Block all public access
   - Lambda has read/write permissions via grantReadWrite()
3. **Updated backend Lambda handler** (attachments.ts):
   - Upload: stores file bytes in S3, metadata only in DynamoDB (storageType='S3')
   - Download: reads from S3 and returns base64-encoded data
   - Delete: removes from both S3 and DynamoDB
   - Backward-compatible: reads legacy items stored in DynamoDB (storageType='DYNAMODB')
   - Falls back to DynamoDB storage when ATTACHMENT_BUCKET env var not set
4. **Updated CDK tests**: 21 tests (up from 19), including:
   - Attachment S3 bucket has AES256 encryption
   - Lambda has ATTACHMENT_BUCKET environment variable
