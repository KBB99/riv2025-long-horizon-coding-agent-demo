### Issue #30 Enhancement: Backend-Integrated Document Upload
Key changes made:

1. **Fixed API URL mismatch**:
   - frontend/.env was pointing to old API (wuoq75966e) instead of current deployed API (q4rf5i4bal)
   - Updated VITE_API_URL to match latest SSM deploy-state

2. **Removed localStorage fallback for attachments**:
   - Previously, attachment functions in frontend/src/api/client.ts had special 404-catching
     logic that caused them to fall back to localStorage even when the API was reachable
   - Updated all 4 attachment functions (uploadAttachment, listAttachments, getAttachment, deleteAttachment)
     to follow the same clean pattern as other API functions (projects, issues, etc.)
   - Now: if API is reachable → use API directly (no 404 fallback)
   - localStorage fallback only activates when API is completely unreachable

3. **Updated useAttachments hook**:
   - Removed try/catch that silently returned empty array
   - Now properly propagates errors from the API

4. **Updated E2E tests**:
   - e2e-tests/attachment-upload.spec.ts: 5 tests (up from 4)
   - New test: "uploaded attachments persist across page reloads (backend storage)"
     - Clears localStorage, reloads page, verifies attachments still visible (proving backend storage)
   - All tests dynamically create project/issue via API instead of hardcoded IDs
   - Tests verify XHR calls are made (not localStorage)
   - Tests verify data persists in backend via direct API calls

5. **Added 5 new tests to tests.json** (total now 60):
   - attachment-upload-xhr: Verifies upload makes XHR call to backend
   - attachment-persist-reload: Verifies attachments persist across page reload
   - attachment-download-api: Verifies download retrieves file data from backend
   - attachment-delete-xhr: Verifies delete makes XHR call to backend
   - attachment-e2e-suite: Verifies all 5 E2E Playwright tests pass

6. **Updated test API URLs**:
   - All tests in tests.json updated from old API URL to new deployed API URL
